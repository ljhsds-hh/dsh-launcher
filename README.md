# DshLauncher DeepSeek Harness 启动器

一个窗口搞定 DeepSeek Harness 的 **清理 → 构建 → 启动**：选好仓库目录，点一下就跑，命令输出逐行实时回显，服务起来后一键打开浏览器，关窗口自动把派生子进程收干净，不留孤儿进程占着端口。

免安装单文件，双击即用（需要本机已装 .NET 8 桌面运行时）。最新版见 **[Releases](https://github.com/ljhsds-hh/dsh-launcher/releases/latest)**：

## 功能特性

- **选目录 + 自动识别 + 记住上次**：点「选择目录…」选定 DSH 仓库目录，程序校验 `package.json` 与 `apps/cli/src/bin.ts` 判断是不是真的 DSH 仓库，校验结果写进日志；配置落盘后下次打开直接回到上次的目录
- **清理 / 构建 / 启动三个动作**：默认对应 `pnpm run clean`、`pnpm run build`、`pnpm dsh web`（与仓库 `package.json` 里的真实脚本一致），命令可在「设置」里改，改完不用重新编译
- **一键执行**：清理 → 构建 → 启动 依次执行，**任一步失败立刻中断**，不会在构建挂了之后还硬去启动
- **实时日志**：标准输出 / 标准错误逐行流式回显，按**内容**分级着色（INFO / WARN / ERROR / SYS）；自动剥掉 ANSI 颜色码与光标控制码，纯控制行与行尾空白丢弃；自动滚到最新（可关）、按关键词过滤、一键复制、导出到文件
- **停止 = 端掉整个 Job**：`pnpm` 会派生 `node → cmd → node` 好几层。实测 .NET 的 `Kill(entireProcessTree: true)` 只杀得到中间层、最深的 node 会活下来（症状就是「点了停止、网页照样能打开」）；改成把进程收进 **Windows Job Object**（`KILL_ON_JOB_CLOSE`），一次 `Terminate` 无论多少层全部收干净（实测 4 层树 0 残留）
- **端口占用拦截**：端口被占用时**直接中止「启动」**并说明原因——端口被占通常说明已有一个 DSH 在跑，再起一个实例会把两边都搞乱；确实需要时可在「设置 → 服务」放开
- **「停止」独立可用，随时把端口抢回来**：这个按钮**永远可点**，不依赖本启动器有没有在跑东西。按下去分三种情况——① 本启动器拉起的进程 → 走 Job 收掉；② 本启动器没在跑但配置端口被别人占着（手动起的、上次没清干净的 DSH）→ 找到占用者并结束它**整棵树**，端口当场释放；③ 端口空着 → 只给一条提示，什么也不做。为安全起见只对 `node` 进程下手，别的程序会明确拒绝并说明
- **就绪检测**：启动后命中日志中的服务地址（默认 `http://127.0.0.1:3080`）即判定就绪，状态栏同步；180 秒内没命中但进程还活着，按已启动处理
- **关窗与服务解耦**：默认情况下**关掉启动器不会停掉已启动的 DSH**，网页继续能用；想停它，重新打开启动器点「停止」即可（会自动找到占着端口的那个进程）。可在「设置 → 服务」勾掉「关闭启动器时保留 DSH 服务」，回到「关窗顺手收干净」的老行为（那种模式下关窗会先弹确认）。清理 / 构建这类短步骤始终会被收掉，免得留下半拉子构建
- **完整日志落盘**：界面里出现的**每一行**都同步写进日志文件，一次运行一个文件，事后可完整复盘这次到底做了什么

## 日志

默认开启（可在「设置」里关掉）。日志目录：

```
%AppData%\DshLauncher\logs\DshLauncher-<启动时间>.log
```

**一次运行 = 一个文件**，所以拿单个文件就能复盘一整次操作。文件里按顺序记录：

| 内容 | 例子 |
| --- | --- |
| 会话开始 / 结束 | `===== 会话开始 =====`、`===== 会话结束（窗口关闭 14:22:31）=====` |
| 运行环境 | 启动器版本、系统版本、.NET 版本、机器名、用户名 |
| 关键路径 | 配置文件路径、本次日志文件路径、工作目录及其校验结论 |
| 端口与命令 | 端口占用情况、清理 / 构建 / 启动 三条实际命令 |
| 目录与设置变更 | 工作目录切换、设置保存后的全部生效值 |
| 每步执行 | `===== 清理 开始 =====`、执行的命令行、工作目录、`===== 清理 完成，用时 1.2s =====` |
| 命令原始输出 | 标准输出 / 标准错误逐行记录（含级别与来源标签，ANSI 转义已剥离） |
| 结束与异常 | `进程已退出，退出码 N`、未处理异常（界面线程与后台线程） |

行格式（毫秒级时间戳，便于还原顺序）：

```
2026-09-20 14:05:33.412 [launcher] SYS   ===== 会话开始 =====
2026-09-20 14:05:41.008 [clean]   INFO  clean: removed 12 paths
2026-09-20 14:05:41.225 [clean]   SYS   进程已退出，退出码 0
```

写入是在后台线程完成的（不阻塞读进程输出），队列排空即落盘；程序被强杀最多丢最后不到一秒的内容。只保留最近 14 个日志文件，更旧的启动时自动清掉。窗口上的「日志目录」按钮直接打开这个目录。

## 界面

两种材质：**浅色机身**（页面底 `#F5F6F8`、白色面板、一套按钮层级）+ **深色日志控制台**（`#0D1117`，把命令输出当"仪表"看，像终端一样有存在感）。窗口分四段：

**Logo 就是这个界面的同一套语言**：蓝色渐变"应用砖"里立着三段向上推进的白色胶囊 = 清理 → 构建 → 启动（和左栏那三张流程卡片、以及卡片左侧的状态色条是同一个意思）。三段从左到右越来越亮，暗示"越靠后的步骤越接近'活着'"。它在 `Assets/app.ico` 里是 **9 帧**：16/20/24/32 用**实心阶梯剪影**（16px 上三条细胶囊 + 两道细缝会被抗锯齿糊成一团，所以小尺寸换成同构图的连通剪影），40/48 起用完整三段式。任务栏、资源管理器、窗口标题栏、设置窗口和 masthead 上的标记全都用它。

| 区域 | 内容 |
| --- | --- |
| masthead | 品牌 + 版本；右侧四个**本工具自己**的工具动作：打开浏览器 / 配置文件 / 日志目录 / 设置 |
| 左栏（白色面板） | **工作区**（路径 + 校验结论 + `选择目录…` / `打开目录` / `检测`）、**流程**（`01 清理` / `02 构建` / `03 启动` 三张状态卡片）、**操作**（一键执行 + 停止一行，单步执行一行） |
| 右栏 | 运行日志标题行（搜索过滤 / 自动滚动 / 清空 / 复制 / 导出）+ 深色控制台。日志行可选中，选中是**深靛蓝底 + 左侧 3px 强调条**，正文本身是浅色，不存在"深字叠深蓝看不清"的老问题 |
| 状态条 | 状态胶囊（圆点按 出错 > 服务运行 > 忙碌 > 空闲 变色）+ 服务地址 + 本次日志文件 + 忙碌指示 |

**"哪个按钮管哪个目录"是说死的**，因为这里最容易看串：

- `选择目录…` 弹系统目录选择框（挑 DSH 仓库）；`打开目录` 在资源管理器里打开**当前工作目录**
- 右上角 `配置文件` / `日志目录` 打开的是**本工具自己**的路径，与 DSH 仓库无关
- 为了一次都不用猜，这几个按钮都带 ToolTip，**直接把要打开的完整路径写在提示里**；`配置文件` 更是用 `explorer /select` 把 `config.json` 本体选中，而不是只丢一个目录让人自己找

有一条硬规矩：**整屏只有一个实心强调按钮**（一键执行），其余一律描边或幽灵，视线第一眼永远落在"下一步该干什么"上。流程卡片左侧那条 3px 色条就是状态本身——等待/透明、执行中/强调蓝、完成/绿、失败/红，用时与状态文案一起显示在卡片右侧。

配色与字号全部走 `Themes/ThemeResources.xaml` 里的 `Ds*` 令牌（加 `Ds` 前缀是为了不覆盖 HandyControl 的同名键），视图层不写死色值。可读性按 WCAG AA 卡过：正文对白底 18.1:1、次级 5.98:1、弱标签 4.74:1；控制台正文对 `#0D1117` 12.3:1，四种级别 7.5–9.8:1。强调色没有直接拿品牌蓝当按钮底——`#4D6BFE` 上白字只有 4.33:1，压深成 `#3B54E8` 才有 5.80:1。

组件策略：**交互控件走 HandyControl**（`hc:Window` / `hc:TextBox` / `hc:SearchBar` / `hc:NumericUpDown` / `hc:CircleProgressBar` / `hc:Tag`），**布局与装饰用 WPF 原生 Border / Grid**（`hc:Card` / `hc:Divider` 的模板给不了想要的圆角与间距精度）；按钮视觉是自己写的 `ControlTemplate`——悬停 / 按下用一层半透明"黑纱"叠在自身底色上，所以同一份模板对深底、白底、透明底都成立。没有用图标字体，状态靠"序号 + 排版 + 色条"表达。文件夹选择用 .NET 8 自带的 `Microsoft.Win32.OpenFolderDialog`；轻提示写底部状态栏（**不用 `hc:Growl`**：它把提示当子元素塞进注册的 Panel，注册成内容 Grid 时提示全落到 Row 0、正好压在「DSH 目录」那一行上，界面看着就崩了）。

## 构建与运行

这是一个**独立仓库**（`github.com/ljhsds-hh/dsh-launcher`），下面的命令一律在**本仓库根目录**执行：

```bash
git clone git@github.com:ljhsds-hh/dsh-launcher.git
cd dsh-launcher
```

依赖 .NET 8 SDK：

```bash
dotnet build Code/DshLauncher.slnx
dotnet run --project Code/src/DshLauncher/DshLauncher.csproj
```

运行测试（133 个用例：默认命令与合并策略 / 配置归一化与存取往返 / 仓库校验 / 日志分级与 ANSI 剥离 / 日志条目格式 / 日志文件写入与清理 / 步骤显示与状态文案 / 设置应用 / Job Object 结构体布局与容错 / 端口归属查询与进程树收集）：

```bash
dotnet test Code/DshLauncher.slnx
```

发布免安装单文件 EXE：

```bash
dotnet publish Code/src/DshLauncher/DshLauncher.csproj -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -o publish
```

产物是**一个** `publish/DshLauncher.exe`（框架依赖的免安装单文件，目标机需要 .NET 8 桌面运行时）。`publish/` 不进版本库，发布走 GitHub Release / Tag。

## 环境与命令

- 命令统一在 **DSH 仓库根目录**（就是你在界面里选的那个工作目录）下通过 `cmd.exe` 执行，与你手敲命令的结果完全一致。之所以走 cmd 而不是直接起 `pnpm`：直接起会绕过 PATHEXT 找不到 `pnpm.cmd`，而 PowerShell 里的 `pnpm.ps1` 又常被执行策略拦住（`无法加载文件 pnpm.ps1，因为在此系统上禁止运行脚本`）
- 输出统一按 UTF-8 解码（pnpm / node / tsx 都按 UTF-8 写管道），中文日志不乱码
- 默认端口 3080；`dsh web` 自己会打开浏览器，所以「就绪后由启动器打开浏览器」默认关着

## 数据存储

`%AppData%\DshLauncher\config.json`，缩进 + 中文不转义，可读、可手改、可进 diff：

**这个文件在首次启动时就会自动生成**（不用先点保存设置或关窗）。原来的写法是"懒创建"，于是第一次用的人点右上角「配置文件」，打开的是一个只装着 `logs` 的空文件夹，看着像工具没生成配置——现在启动时先落一份（并把界面当前显示的目录一起写进去），那个按钮点下去永远有东西可看，而且会**直接选中 `config.json` 本体**。

| 字段 | 说明 |
| --- | --- |
| `workspacePath` / `recentWorkspaces` | 上次 / 最近的仓库目录（最多保留 8 个） |
| `steps[]` | 三步的 `id` / `name` / `command` / `longRunning` |
| `serverPort` | 服务端口（默认 3080），用于占用检测与「打开浏览器」 |
| `allowStartWhenPortBusy` | 端口被占用时是否仍允许启动（默认关） |
| `keepServiceRunningOnExit` | 关闭启动器时保留 DSH 服务（**默认开**；关掉则关窗顺手收干净） |
| `readyPattern` | 就绪判定正则 |
| `maxLogLines` / `autoScroll` | 日志保留行数与自动滚动 |
| `writeLogFile` | 是否把日志同步写入文件（默认开） |
| `windowWidth` / `windowHeight` | 窗口尺寸记忆 |

命令缺失会自动补默认值，**用户已经改过的命令不会被升级覆盖**；文件损坏或字段越界一律回退默认值，绝不挡住启动。
