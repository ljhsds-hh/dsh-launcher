## 1 总体概述

### 1.1 产品定位

DeepSeek Harness 是本机从源码跑的（`node --import tsx/esm apps/cli/src/bin.ts web`），日常要「清理 → 构建 → 启动」就得来回开终端敲命令，还要盯着输出。

本工具把这条链路收进一个窗口：**选一次目录，之后点按钮就行**，命令的每一行输出实时出现在界面里，服务起来一键开浏览器，关窗口把子进程收干净。

### 1.2 核心约束

- 技术栈强制 .NET 8 + HandyControl，HC 没有对应组件时才允许 WPF 原生控件。
- **绝不改动 DeepSeek Harness 源码**：只作为外部进程调用它自己的 pnpm 脚本。
- 命令必须可配置，不能硬编码在代码里——DSH 换脚本不该需要重新编译本工具。
- 单机单用户，无需登录与联网。

### 1.3 术语定义

| 术语 | 含义 |
| --- | --- |
| 工作目录 | DeepSeek Harness 源码仓库根目录，所有命令在此目录下执行 |
| 步骤 | 一个可执行动作：清理 / 构建 / 启动 |
| 步骤 ID | `clean` / `build` / `start`，用于日志来源标签与配置定位 |
| 常驻步骤 | 启动后持续运行的步骤（`dsh web`），需手动停止 |
| 就绪 | 启动后日志中出现匹配 `readyPattern` 的内容，视为服务已可用 |
| 进程树 | cmd.exe → pnpm → node 这条运行链，停止时必须整棵收起 |

## 2 功能需求

### 2.1 工作目录

| 项 | 说明 |
| --- | --- |
| 选择 | 「选择目录…」打开系统目录选择框（`Microsoft.Win32.OpenFolderDialog`）。按钮不叫「浏览」，因为和「打开目录」太像、一看分不清哪个是选哪个是开 |
| 手输 | 路径框可直接编辑 |
| 校验 | 同时存在 `package.json` 与 `apps/cli/src/bin.ts` 才判定为 DSH 仓库；「检测」按钮输出校验结论，缺失项逐个列出（如「缺少：apps\cli\src\bin.ts」） |
| 记忆 | 上次目录写入配置；启动时按「上次目录 → 最近目录（最多 8 个）→ 默认候选」顺序取第一个合法目录 |
| 打开 | 「打开目录」在资源管理器中打开**当前工作目录**（不是本工具自己的目录）；ToolTip 里直接显示将要打开的完整路径，避免与右上角「配置文件 / 日志目录」看串 |

**执行前置条件**：三个动作执行前都重新校验工作目录，不合法直接拒绝并在日志给出原因，不启动进程。

### 2.2 步骤与命令

| 步骤 | 默认命令 | 常驻 |
| --- | --- | --- |
| 清理 | `pnpm run clean` | 否 |
| 构建 | `pnpm run build` | 否 |
| 启动 | `pnpm dsh web` | 是 |

- 默认值取自 DSH 仓库 `package.json` 中真实存在的脚本（`clean` → `tsx scripts/clean.ts`，`build` → `tsx scripts/build.ts`，`dsh web` → `node --import tsx/esm apps/cli/src/bin.ts web`）。
- 命令在「设置」里可改；保存后立即对后续执行生效，无需重启程序。
- 配置里缺少某个步骤时自动补默认值；已有步骤的**自定义命令不被覆盖**。

### 2.3 执行

#### 2.3.1 单步执行

清理 / 构建 / 启动各有独立按钮，点击即执行该步。

#### 2.3.2 一键执行

按 **清理 → 构建 → 启动** 顺序执行：

- 任一步失败（非 0 退出码）**立即中断**，不继续后续步骤。
- 常驻步骤（启动）跑起来后流水线即结束。
- 执行期间单步按钮与一键执行按钮置灰，避免并发执行。

#### 2.3.3 前置处理

执行任一步之前：

- 若已有进程在运行，先停止它并等待 400ms（pnpm 派生的子进程会占住构建产物与端口）。
- 若执行的是常驻步骤且目标端口已被占用，**中止本次「启动」**并说明原因（默认行为，可在设置中放行）。
  端口被占通常意味着已有一个 DSH 在运行；Windows 的 `SO_REUSEADDR` 允许两个实例绑同一端口，
  放任下去会出现「两个 DSH、谁也说不清谁在服务」的局面。

### 2.4 进程执行与日志

| 项 | 要求 |
| --- | --- |
| 执行方式 | 通过 `cmd.exe /d /s /c "<command>"` 在工作目录下执行 |
| 编码 | 标准输出与标准错误统一按 UTF-8 解码，中文不乱码 |
| 回显 | 逐行实时回显，不缓冲、不等进程结束 |
| 清洗 | 剥掉 ANSI 转义序列（CSI / OSC / 两位转义）与其余控制字符（保留制表符），去掉行尾空白；清洗后为纯空白的行直接丢弃（进度刷新会留下大量这类噪声） |
| 分级 | **只按内容判定，不看输出流**。命中 `error TS<数字>` / `error:` / `ERR!` / `ELIFECYCLE` / `ENOENT` / `EADDRINUSE` / `EACCES` / `EPERM` / `Cannot find` / `Module not found` / `Unhandled` / `Exception` / `Traceback` / `失败` / `错误`，或整词大写的 `ERROR` → ERROR；命中 `WARN` / `WARNING` / `警告` / `deprecat` → WARN；其余 → INFO |
| 为何不看输出流 | pnpm 的脚本横幅、rolldown 的 `[PLUGIN_TIMINGS]` 提示、MCP 服务器的 ready 消息、大量空行全部走 stderr。早期版本把 stderr 一律判为错误，一次正常构建刷出 593 行假 ERROR（按真机日志回放修复后为 0）。真正的成败由退出码表达 |
| 来源 | 每行带步骤 ID 标签（`clean` / `build` / `start` / `launcher`） |
| 时间 | 每行带时:分:秒 |

### 2.5 停止

- 一次点击结束**整棵进程树**。实现方式是把进程收进 **Windows Job Object**
  （`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`），停止时 `TerminateJobObject`。
  **不用 `Process.Kill(entireProcessTree: true)`**：实测在 `cmd → node → cmd → node` 四层树上
  它只杀掉中间两层、最深的 node 会活下来（用户真机症状：点了停止，网页照样能打开）。
  Job 是内核级归属，后代再派生、父进程先死都不影响，一次收干净（实测 4 层树 0 残留）。
- Job 句柄在 `Dispose` 时关闭，`KILL_ON_JOB_CLOSE` 会连带收掉全部后代：
  关掉启动器不会留下还在跑的 DSH（用户真机症状之一）。
- Job 创建失败时退回 `Process.Kill(entireProcessTree: true)`，再失败退回 `taskkill /F /T /PID`，
  并在日志中给出提示。
- **「停止」永远可点**（不依赖本启动器是否在跑东西），按下去分三种情况：
  1. 本启动器拉起的进程在跑 → 结束整个 Job（上面那条）；
  2. 本启动器没在跑，但配置端口被别人占着 → 用 `GetExtendedTcpTable` 查出占用者 PID，
     确认是 `node` 进程后结束它**及其全部后代**，然后复查端口是否释放；
     **只对 `node` 下手**，其它程序明确拒绝并说明原因；
  3. 端口空着 → 只写一条提示，不做任何操作。
- 结束外来进程树时必须**先把整棵树的 PID 收集完再动手**：父进程先死会让子进程被重新挂载，
  边杀边找一定漏。收集时还要用「子进程不可能比父进程先诞生」剔除 PID 复用造成的假父子链接。
- 停止过程中当前步骤状态置为「已中止」，不显示为「失败」。
- 停止后流水线终止，端口释放。

### 2.6 就绪检测

- 常驻步骤启动后，监听日志行是否匹配 `readyPattern`（默认 `https?://(?:127\.0\.0\.1|localhost):\d+`）。
- 命中的地址作为服务地址显示在状态栏，并作为「打开浏览器」的目标。
- 判定顺序：命中就绪日志 → 成功；进程提前退出 → 失败；180 秒超时但进程仍存活 → 按已启动处理（并记录一条 WARN）。
- 用户主动停止时一律判为「已中止」，不判失败。
- 用户填写非法正则时放弃就绪判定，由超时逻辑兜底，不抛异常。

### 2.7 日志区

| 功能 | 说明 |

| 滚动 | 默认自动滚到最新一行；可在界面取消勾选 |
| 过滤 | 关键词过滤，匹配「内容 / 来源 / 级别」，忽略大小写 |

### 2.8 日志落盘（完整复盘）

| 项 | 要求 |
| --- | --- |
| 开关 | 默认开启，可在「设置」中关闭；关闭时不产生任何日志文件 |
| 位置 | `%AppData%\DshLauncher\logs\DshLauncher-<启动时间>.log` |
| 粒度 | **一次运行一个文件**；界面里出现的每一行都必须落盘（含未处理异常） |
| 行格式 | `yyyy-MM-dd HH:mm:ss.fff [来源] 级别  内容`，毫秒级便于还原顺序 |
| 必录内容 | 会话开始 / 结束标记、启动器版本与运行环境、机器名与用户名、配置文件与日志文件路径、工作目录与校验结论、端口占用情况、三条实际命令、工作目录切换、设置保存后的全部生效值、每步的开始与完成（含退出码与用时）、命令的原始输出逐行、未处理异常（界面线程与后台线程） |
| 写入方式 | 后台线程异步写入，**不得阻塞**读进程输出的线程 |
| 落盘时机 | 队列排空即 flush；程序被强杀最多丢最后不到一秒的内容 |
| 保留策略 | 只保留最近 14 个日志文件，更旧的启动时清理 |
| 容错 | 写入失败不得影响主流程；失败原因记录在 `LogFileWriter.LastError` |
| 入口 | 主窗口提供「日志目录」按钮直接打开该目录 |

### 2.9 设置

「设置」窗口可改：三条命令、端口、端口被占用时是否放行、就绪正则、就绪后是否打开浏览器、是否自动滚动、日志保留行数，并显示日志目录与配置文件路径。

- 编辑的是内存副本，点「保存」才写回并落盘，中途关闭不污染当前配置。
- 命令为空白时不覆盖原命令；端口越界回落 3080；日志上限夹到至少 200。

### 2.10 退出保护与「关窗不停服务」

关闭窗口时是否停掉 DSH，由 `keepServiceRunningOnExit` 决定（**默认 true = 保留服务**）：

| 取值 | 行为 |
| --- | --- |
| true（默认） | 关窗**不停** DSH：只摘掉日志、销毁 Job 句柄，服务继续在后台跑；不弹确认框。想再停它，重新打开启动器点「停止」——它会按端口找到那个进程（见 2.5 情况 ②） |
| false | 恢复老行为：若本启动器自己起的进程还在跑，先弹确认；取消则窗口不关，确认后先保存窗口尺寸与目录，再结束整个 Job 并退出 |

实现要点：

- 「保留」要求 Job **不能**带 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`（带了的话句柄一关系统就会连带结束进程）。
  所以 Job 在创建时就按 `长驻步骤 && 需要保留` 决定是否加这个标志；**短步骤（清理 / 构建）始终加**，
  免得关窗留下半拉子构建。
- `ProcessRunner.StopAsync` 的显式停止**永远**走 `TerminateJobObject`，与关窗行为无关——
  即「关窗保留」不会削弱「点停止就真停」。
- 关窗保留时必须在日志里写清楚（否则事后复盘会以为服务被停了）。

## 4 数据持久化

`%AppData%\DshLauncher\config.json`：

**首次启动即自动生成**（`ConfigService.SaveIfMissing`）：不能等用户"保存设置或关窗"才写文件，否则新用户点右上角「配置文件」只会看到一个装着 `logs` 的空目录。生成时把界面当前解析出来的工作目录一并写入，保证文件内容与界面一致。「配置文件」按钮用 `explorer /select` 打开并选中该文件本体。

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `workspacePath` | 空 | 上次使用的仓库目录 |
| `recentWorkspaces` | `[]` | 最近目录，最多 8 个 |
| `steps[]` | 三步默认值 | `id` / `name` / `command` / `longRunning` |
| `serverPort` | 3080 | 越界回落 3080 |
| `allowStartWhenPortBusy` | false | 端口被占用时是否仍允许执行「启动」 |
| `keepServiceRunningOnExit` | true | 关闭启动器时是否保留 DSH 服务 |
| `openBrowserWhenReady` | false | `dsh web` 自身会开浏览器，默认不重复开 |
| `readyPattern` | `https?://(?:127\.0\.0\.1\|localhost):\d+` | 空白回落默认值 |
| `maxLogLines` | 5000 | 小于 200 回落 5000 |
| `autoScroll` | true | — |
| `writeLogFile` | true | 是否把日志同步写入 `logs\` 目录 |
| `windowWidth` / `windowHeight` | 1120 / 760 | 过小回落默认值 |
| `printEnvironmentOnStart` | true | 启动时把配置文件路径、工作目录校验、端口占用情况写进日志 |

要求：

- 缩进 + 中文不转义（`JavaScriptEncoder.UnsafeRelaxedJsonEscaping`），文件可读可手改。
- 文件不存在 → 默认值；文件损坏 / 反序列化失败 → 默认值，不弹错、不阻止启动。
- 写入失败不打断用户操作。
- 读取时统一归一化，保证被改坏的配置也能启动。

## 5 质量要求

- 单元测试 133 个用例，覆盖：默认命令与合并策略（保留自定义 / 补缺失 / 回填空命令 / ID 大小写）、配置归一化（端口、日志上限、窗口尺寸、就绪正则、空目录列表、空步骤）与存取往返（可读中文、损坏回退）、仓库校验与描述文案、ANSI 剥离（CSI / OSC / 光标控制 / 中文保留 / 控制字符 / 纯转义行）、日志分级（常规构建输出不误报、真错误、警告、优先级、大小写、统计行）、日志条目格式、日志文件写入（行格式、批量顺序、文件名规则、UTF-8 中文、目录自建、关闭时不建文件、运行中关停、同秒不撞名、清理与保留）、步骤状态到文案的映射与变更通知、设置的应用与越界处理、Job Object 的创建（带 / 不带 KILL_ON_JOB_CLOSE 两种，验证结构体布局）/ 重复释放 / 不结束式释放 / 收编已退出进程的容错、端口归属查询（占用与释放两种状态、PID 必须是自己）与进程树收集（含自己、不存在的 PID 只返回自身、不误拉无关进程）。
- `ConfigService` 与 `LogFileWriter` 都支持注入目录，测试用临时目录，不污染真实 `%AppData%`。
- 执行链路走真实进程（`cmd.exe`），逻辑上保证：整棵进程树停止、UTF-8 解码、异常不导致程序崩溃。
- Release 配置发布 win-x64 免安装单文件 EXE：
  `dotnet publish Code/src/DshLauncher/DshLauncher.csproj -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -o publish`，
  产出单个 `publish/DshLauncher.exe`（框架依赖，目标机需装 .NET 8 桌面运行时）。
